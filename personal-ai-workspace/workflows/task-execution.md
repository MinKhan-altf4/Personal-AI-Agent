# Workflow — Task Execution

## 1. Intake
Capture the request, desired outcome, project, constraints, and expected deliverable.

## 2. Context
Read `PROJECT_CONTEXT.md`, `AGENTS.md`, and relevant project documents.

## 3. Plan
Define tasks, dependencies, acceptance criteria, primary agent, tools, and permission level.

## 4. Execute
Use the smallest sufficient agent team. Keep changes scoped and record blockers.

## 5. Verify
Check deliverables against acceptance criteria. Use QA for complex, high-impact, or multi-agent work.

## 6. Report
Return status, actual actions, evidence, issues, and recommended next action.

## 7. Preserve
Update project knowledge or decision records only when the information is durable and authorized.

## Status definitions
- `pending`: not started
- `in_progress`: actively being worked on
- `review`: awaiting verification or approval
- `completed`: acceptance criteria verified
- `partial`: some deliverables completed, some remain
- `blocked`: cannot proceed without missing input or access
- `cancelled`: owner cancelled the task
